# Deterministic gateway — rules-v1

Implemented 24 October 2026. POST /api/validations accepts only {proposalId}; GET /api/validations/:id retrieves a stored decision. Both require a current same-tenant staff session; POST also requires Origin/CSRF. Customers cannot see staff validation evidence. No endpoint accepts client identity, policy, evidence, provider state, decision or gateway mode.

The backend resolves stored proposal/request/receipt/approval, current account roles, resource ownership, active policy, structured policy rules and evidence references. It records BLOCK, REVIEW_REQUIRED or READY with named checks, source IDs, timestamp, rules version, trusted mode and the observed provider-state snapshot. BLOCK takes precedence over review. Known action/target/amount/currency/ownership/policy/authority mismatches block; missing confirmation/approval/evidence, unsupported or ambiguous actions and unknown state require review. Corrections need their own stored proposal and validation. Model confidence and text instructions are never inputs to permission.

Migration 002 adds structured policy rules, approved source versions and passages, request-version-scoped evidence records/manifests, validations/checks and the operation table used by the reservation milestone. There is no public ingestion endpoint for these trusted sources. A later approved retrieval adapter must verify and populate them; reviewer labels and memory cannot populate authority.

Policy rules define cancellation/refund eligibility and a positive MYR minor-unit refund maximum, with an exact approved policy passage and fixed REFUND_APPROVER role. The supported simple cases also require fresh paid-payment balance or active subscription state. Complex billing is held. Refunds require valid customer confirmation and exact-amount approval independently of business eligibility.

Provider reads are typed, bounded to 3 seconds and cannot receive model-selected URLs or payloads. Observations must match tenant/customer/target, test environment and action kind; refunds require MYR and current remaining refundable balance. Observations older than 5 seconds, unknown balances/states, pending payments, complex billing or already scheduled cancellation require review. The backend reloads authority and sources in a transaction after the asynchronous read before recording a decision. Reads are skipped when structured checks already block or require review.

The runtime defaults to LIVE_TEST and has no connected provider reader or approved live retrieval sources. Consequently legitimate local fixtures remain REVIEW_REQUIRED. CONTROLLED_TEST is an injected code-only test harness mode; it is stored on every result and cannot be enabled by HTTP/environment input. Only this harness currently demonstrates READY. No provider writes occur and executionEnabled stays false for every response. Real inference/retrieval/Stripe access gates remain unfinished.

The same gateway is the rules-only baseline and must remain the authority boundary for one-shot and adaptive investigator variants. The draft held-out corpus has not been run; passing engineering tests is not held-out evaluation evidence.

The second gateway milestone implements persistent resource leases, atomic operation reservation/receipt+approval consumption and an isolated service-authenticated reservation API. See [operation reservation](OPERATIONS.md). Provider submission/reconciliation remain unimplemented.
