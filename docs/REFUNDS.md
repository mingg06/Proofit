# Exact refunds and shared execution

Cancellation and refunds now use apps/executor/execution.ts as their single durable submission/reconciliation coordinator, with action-specific drivers. OperationLedger remains the sole owner of reservation, exact authority consumption and stable business/provider keys. No duplicate approval or operation state was introduced. Migrations 005/008/009 do not replace the ledger; 008/009 add memory/jobs only.

RefundExecutor accepts only validationId, reserves the stored REFUND_PAYMENT action, and freshly checks receipt/approval/policy/ownership and remaining refundable balance before claiming one submission. Duplicate workers cannot claim another attempt. A timeout/lost acknowledgement stays OUTCOME_UNKNOWN and reconciles the same operation, never creates another key. Reconciliation tasks are action-filtered and fenced; a replacement lease defeats late results.

StripeRefundAdapter uses installed stripe 23.0.1/API 2026-09-30.endive. It accepts test credentials only; verifies the provider account, false livemode, mapped customer/resource, exact paid/captured MYR card payment, and a complete bounded refund list. Complex/disputed/transferred/application-fee/manual-capture/non-card cases are held. Pending refunds reduce the available balance. Integer minor-unit sums are checked for safe bounds. Only the exact payment_intent, amount, operation metadata and persisted idempotency key are submitted. No refund email, bank arrival or live-money result is claimed.

Lost responses are located by stable proofit_operation_id metadata in the charge's complete refund list. Missing/multiple/mismatched results remain uncertain. A 100-result overflow/pagination flag is held for review rather than treated as a complete balance. Provider observations must match tenant/customer/payment/operation/refund ID, exact amount/currency, provenance and fresh monotonic timestamps. PENDING, FAILED, CANCELED and unknown stay distinct. A provider SUCCEEDED observation does not prove receipt by a customer's bank.

Official SDK/API references checked: https://docs.stripe.com/api/refunds/create and https://docs.stripe.com/api/refunds/list plus installed SDK type declarations. Controlled adapter and executor tests cover exact bindings, absent/revoked approvals, balance changes, concurrency, pending/failed/canceled observations, wrong amounts, lost responses and database restart. No genuine Stripe refund is claimed. Default startup still refuses provider keys and exposes no provider write/read routes. Installing the real runtime remains gated on manual integration access/evidence.
